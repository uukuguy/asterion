### feedback — model reasoning and cognition

Let the LLM organize hypotheses, representations, experiments, programs, NOTES and strategy. Supply strong infrastructure, tools, actual observations and enforceable boundaries. Do not replace useful reasoning with execution-log accumulation, mandatory tiny cognition steps or hand-written solving hints. Actor programs/automatic continuation count as autonomous work; disclose outer solving intervention.

### feedback — approved architecture

Do not reopen agreed Prime/native direction from old branch notes. Independent applications consume a reusable Prime library; central registration or a CLI must not become prerequisites. User model preferences and application ownership are authoritative in AGENTS and D-2026-10-10-03. Keep P2 capability work separate from migration.

### feedback — proportionate verification

Review changed implementation, necessary boundary assertions and small relevant regressions. Avoid repeated release-scale/full-combination gates or unrelated suites during research. A frozen gate answers one measurement, not another hardening round. Verify behavior and deltas, not grep counts, fixture resemblance or a subagent's reported completion. Freeze reviewed source before its final packaged witness. Sources: user steering2026-09-14,2026-10-11/12.

### feedback — evidence and causal attribution

A stage label or an RPC filename is not a cause. Trace the actual producer, response and dispatch state before blaming Pi or another layer. Reconcile a diagnostic with known successful runs. Search PATH and real environment before saying a resource is absent. Capture acknowledgement, values and code-path evidence; distinguish no dispatch from unknown execution. Take contracts from producers, check affected boundaries and reconcile recurring defects. Keep narrow failures narrow.

### feedback — research process review

Track whether P7's macro research organization is useful, stalled or anomalous: actual hypotheses, modeling/search, experiments, feedback and revisions. Visible pixel changes are action effects, not objective progress or safety. Judge understanding by its use in later decisions. User-defined checkpoints are completed assigned targets; six levels were not a demonstrated solving ceiling. Route variation across different code/context/budgets cannot automatically be attributed to randomness.

### feedback — experience, console and sharing

Preserve privately complete successful and failed research, counterexamples and useful programs. New fresh research excludes prior experience unless explicitly selected; an instructed continuation reuses its admitted checkpoint. Replay displays native saved judgments and never uses another LLM to invent missing history. HUMAN play is independent of P7 research. Keep console layouts compact, scores legible and selections persistent. Public results/projections stay separate from private archives and credentials.

### feedback — integration and autonomy

Completed work should be integrated into main, committed and pushed promptly. Use subagents for concrete bounded tasks under AGENTS; judge them by delivered work and verify integration. Preserve other workers' edits and unrelated worktrees/processes. Do not repeat authorization or provider/budget questions for an already authorized preset.

### feedback — final handoff

When the user says `handoff`, complete final closeout directly: stop this session's leftovers, persist verified facts/current judgments/history/open boundaries, correct core state and memory pointers, commit/push and leave Git clean. Do not hand the user another draft to approve. Keep scope necessary; do not create another state hierarchy. The repo AGENTS handoff contract overrides a generic skill's draft-review convention.

### feedback — resource reporting

Report restoration versus new actions, per-level versus whole-game scores, attempted versus effective evaluations and source versus deployed evidence separately. Token totals are throughput; cache fractions and labelled cost estimates are different facts. Missing or partial data stays unknown; an SDK estimate is not an invoice. Deaths are not automatically research failure, but avoidability from prior evidence and actual probe authority must be checked. A solved level need not be rerun solely for a bounded gate/summary repair when exact saved evidence and a targeted witness suffice.

### feedback — application budgets

A low inherited cap is an application integration problem, not a reason to ask the user to micromanage a budget. Applications must supply suitable finite execution presets. Model risk/cost declarations alone are not operator permission; finite unknown-risk research must preserve the distinction between accepting risk and establishing safety. Technical policy: D-2026-10-13-03.
