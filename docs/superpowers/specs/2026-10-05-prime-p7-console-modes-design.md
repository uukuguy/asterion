# P7 控制台三模式整体设计

日期：2026-10-05。状态：用户已确认（2026-10-05）。已按用户要求修正为 P7 自主解题主流程。回放和首包实时 P7 已实现并完成无模型检查；真实打包运行待验证。可恢复暂停与独立人工验证尚未实现。

## 核心目标

控制台以 P7 自主过关为中心。主画面显示真实游戏。认识区显示逐步完善的玩法介绍。过程区显示 P7 的目标、决策摘要、动作、反馈和认识更新。假说补足认识，帮助继续玩，不要求逐条验证后才能规划。

人工模式只用于手工验证尝试。它有独立的游戏实例、会话和记录，不接管 P7 的局，不把人工动作、观察、笔记或结果自动加入 P7 的历史、认知、实验、记忆和规划输入。两者共用界面和游戏执行基础，不共用正在推进的局或内部工作流。

沿用单个自包含 HTML、内嵌 Tailwind CSS 与原生 JS。离线文件可独立回放。实时操作需要本地 Python 服务；前端无需构建步骤或 CDN。本次不增加并行游戏调度、人工辅助 P7 和官方提交功能。

## 方案选择

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 共用界面，独立 P7 与人工会话（采用） | P7 是主流程；人工验证独立；复用展示与执行基础 | 需隔离记录与持久化入口 |
| 同一局人工/P7 交接（撤回） | 可以人工续玩 P7 的局 | 人工动作进入 P7 求解过程，不符合用户要求 |
| 浏览器内另做游戏与求解 | 浏览器可直接执行 | 重复现有 Python 执行链，改变部署边界 |

## 模式与操作

| 模式 | 定位 | 主画面与动作键 | 主要控制 |
| --- | --- | --- | --- |
| P7 自主解题（主模式） | 自主观察、认识、规划和过关 | 实时画面；高亮 P7 当前动作；按键供观察 | 启动、暂停/继续、结束 |
| 回放 | 检查已有过程 | 历史真实帧；按键定位已录动作 | 播放、暂停、时间轴、前后动作 |
| 人工验证 | 独立手工尝试 | 独立实例的实时画面；按键执行单次动作 | 新开验证局、动作、重试、结束 |

界面默认进入 P7 工作区。启动控制台本身不调用模型；点击启动后，P7 使用已有 operator 配置与有限预设自主推进。正常求解不需要人工逐步批准动作。人工验证放在次级入口。

动作区只放按键、短含义与小状态标记，例如 `ACTION4 · 右移 · 已识别`。完整依据放在认识与过程区。含义来自已保存的认识或明确标记的推断，不按编号预置方向。P7 模式的按键不发送人工动作。人工模式显示该局可用动作，不套用其他局的认识；如以后显示 P7 参考资料，必须另标来源并保持只读。

回放含义若来自最终认识，注明“最终动作认识”。实时 P7 模式显示当前认识版本。不能把最终认识当作历史时点已经获得的认识。

人工操作采用本帧 `available_actions`。坐标动作仅在可用时启用。键盘控制只在游戏区获得焦点时启用；禁止按住键重复发送和忙碌时排队旧动作。RESET 显示“重试当前关卡”，保留已完成关卡和本局记录。

默认只显示真实游戏画面。变化格、动作位置和前后对照是可选覆盖层，默认关闭。颜色采用名称加编号。不能由开发者把本题某个色块直接解释为目标、分数或进度。

顶部显示模式、题目、关卡、游戏状态和连接状态。历史回放、实时 P7 和独立人工局必须清楚区分。查看回放不自动暂停正在运行的 P7；界面注明后台任务是否仍在运行。返回实时视图获取最新观察。

## 题目与关卡管理

题目列表读取本地目录的公开元数据：ID、别名、关卡数和可用记录。P7 工作区显示题目、当前任务与最近结果；没有记录时显示题目列表，不要求填写长路径。

关卡完成只依据游戏权威的 `levels_completed` 或 WIN。列表区分“已过关”“进行中”“未开始”“没有记录”。未观察到的关卡不生成假画面。P7 成绩与人工验证结果分别统计，人工完成不能改变 P7 完成状态。

首版只运行一个活动游戏实例。新开人工局前，必须等 P7 结束或显式结束 P7。人工局结束后启动 P7，会建立独立 P7 运行；不恢复人工位置，也不复制人工动作前缀。回放不创建引擎。未来如支持历史状态重建，仍须明确标记来源，不能算新的自主求解。

## 会话与隔离边界

Python 应用层管理两种会话：P7 运行会话和人工验证会话。模式在创建时固定。每局有独立的 `session_id`、`episode_id`、观察版本、连续动作/事件序号、记录目录与结果。

P7 会话沿用自身 broker、模型运行、认识与学习路径。人工会话复用游戏引擎和必要的动作合法性、坐标、串行执行及有限资源检查，不挂载 P7 的模型、认知实验、学习服务或共享记忆写入器。不能直接用会自动更新 P7 认知的工具桥处理人工动作。复用 broker 时必须显式禁用相关服务，并验证不存在隐式学习或持久化写入。

人工隔离覆盖动作期间与会话收尾：不执行经验归纳，不读取或写入 P7 cognition、semantic cognition、game mechanics、playbook，也不发布可被 P7 prefix/attempt 加载器发现的记录。仅把可选认知 store 设为 None 不视为完成隔离；现有 broker 有先归纳、后检查 store 的路径，现有 P7 收尾还会保存 playbook。人工入口需要明确的无学习执行路径和独立收尾。

P7 上下文与既有经验读取只选择 P7 来源。人工记录使用独立来源和存储范围；按同游戏 ID 查询不能越过这一边界。人工局退出、结束或切换界面均不触发 P7 对人工轨迹的自动分析。

人工写命令带命令 ID 和当前观察版本。先查去重记录，再检查版本。同 ID、同内容返回原结果，不重复执行；同 ID、不同内容被拒绝。旧会话、旧观察和忙碌时的新动作被拒绝。暂停或结束 P7 不依赖不断变化的观察版本。

P7 暂停需要关闭新动作入口并等待当前调用结算。多步调用尚未完成时显示“等待结算”。保留当前 P7 局与自身上下文后才可称为暂停；继续时仍由 P7 规划。现有取消会终止运行，不能仅改标签称为暂停。首个实时版本先接真实启动和结束，再实现可恢复暂停，不引入人工接管或 solver handoff。

阶段目标、动作预算和终局收据保持现有独立 witness 语义，不为人工续玩改变 broker 的目标。预算耗尽不能重建 broker 续预算。可 RESET 的 GAME_OVER 显示“需要重试”；重试增加 episode，动作和事件序号持续递增。模型轮次独立记录，不与关卡重试混淆。

## P7 过程与认识

核心关联链是 `观察版本 → P7 决策摘要 → 动作 → 结算观察 → 认识更新 → 后续规划`。每条记录带 P7 运行、轮次、关卡与动作序号。摘要包含目标、简短依据、选中动作与预期反馈，由 P7 显式输出。不从工具调用倒推理由，也不要求展示私有思维链。

一个决策可以对应多步动作。每步有真实前后帧、结果与关卡进度。动作后显示物件变化、状态变化、P7 对反馈的解释以及认识修改。缺少 P7 解释时注明缺失；像素测量不能冒充 P7 结论。

稳定游戏认识是一份逐步完善的玩法介绍：类型、物件、控制、规则与过关条件。确定事实、规划推断和未知项明确区分。中文采用短句、固定术语、明确主体和条件的简化技术写作原则，不宣称通过英语 ASD-STE100 认证或未经评估的百分比。

假说针对介绍中的缺口与过关阻碍。常识和高置信推断可以先用于规划，在正常动作中顺便检验。一个动作可支持或否定多个相关假说。策略与假说分别记录。分数、进度、计时、资源与状态部件由 P7 观察和反馈识别，提示只提醒注意这些部件，不填入本题答案。

认识更新带 `cognition_revision` 和证据观察/动作关联。回放选择对应历史版本；旧记录仅有最终认识时保留范围提示，不补造过去的版本。默认显示玩法介绍与本轮差异，全部假说依据可展开。

人工模式只显示自身真实动作、前后画面和游戏反馈，不生成 P7 决策、假说或认识更新。人工笔记如需保存，也属于独立验证记录。本设计不提供“交给 P7”“接管 P7”或“导入人工经验”入口。

## 接口与部署

服务代码仅放在 `src/asterion/applications/prime/p7/`。复用 `ArcadeEngine`、现有 P7 operator 与打包页面资源。通用 runtime、runner 和闭合协议不增加游戏专用逻辑。

浏览器提供固定操作：题目列表、读取记录/快照、订阅事件、启动/暂停/继续/结束 P7，以及创建/操作/结束独立人工局。人工命令只能到达人工会话。浏览器不指定 shell 命令、路径、provider、model 或无限预算。

服务绑定 loopback，页面与 API 同源。写请求校验服务令牌、Origin 和会话身份。离线 HTML 保持 `connect-src 'none'`；实时页面只连接本地同源接口。事件不含密钥、私有路径、provider 原始载荷或未公开模型输出。

现有真实运行由 Mac 调用 Orb guest。引擎、broker 与 P7 在同一执行侧；Mac 服务通过固定受控通道转发请求/事件。guest loopback 不等于 Mac loopback，现有内部 `P7ClientServer` 与 IPython bridge 不直接作为浏览器 API。

事件使用应用级安全投影，带连续序号和明确关联。有限缓冲支持重连；缺口超出范围时重新读快照。P7 与人工记录分别可导出单个离线 HTML。

最终日常入口为 `make p7-console`：打开 P7 工作区，另可选择回放或人工验证。`make asterion-prime-p7-console` 保留只导出功能。`make p7-console` 现已进入实时工作区；首包支持固定有限 L1 任务的启动和结束。可恢复暂停和独立人工验证尚未实现。

## 异常与结果

浏览器断线不自动中断自主 P7。任务在宿主仍存活且有限预算内继续运行；重连读取状态，不重复启动模型。人工断线不排队或重复动作，通过命令 ID 查询结果。服务或 guest 进程退出按中断记录处理，不承诺恢复已失去的引擎。

引擎异常且无法确认动作是否生效时，锁定该会话并显示“游戏状态不确定”，不自动重试动作。服务退出负责关闭引擎和模型进程。主动 P7 暂停与浏览器断线是不同事件。

P7 收据只包含该自主运行的动作。人工结果只写人工记录。正常未完成、用户结束、预算耗尽和引擎故障分别显示；成功导出、页面交互和人工过关不证明 P7 能力。

## 实施顺序与验收

1. **P7 实时主流程**：共用界面接现有自主运行，提供题目选择、启动/结束、真实帧与事件流。补齐决策摘要、动作结果和认识版本关联。先完成主流程，不等待人工功能。
2. **P7 运行观察与控制**：实现真实暂停/继续、记录重连与回放切换。暂停仍属 P7 会话，不提供人工动作入口。
3. **独立人工验证**：新建人工实例，提供按键、坐标、重试与记录。验证不调用模型、不执行经验归纳、不读写 P7 认知/经验、不改变 P7 结果；检查动作与收尾路径，并验证人工记录不会被 P7 prefix/attempt 或上下文加载器选中。
4. **打包部署闭环**：验证 Mac/Orb 通道、wheel 资源、真实有限 P7 level-witness 和独立人工动作。执行相关 Python/DOM、lint、docs-check 和 promotion-check；扩展注册若改变，另执行 TypeScript 扩展测试。未通过的检查和实际过关结果如实报告。

核心验收是 P7 自主观察、规划、执行并利用反馈继续推进，过程可查。人工验证验收是操作有效且与 P7 工作流隔离，不以双方交接为目标。
