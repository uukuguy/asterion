# P7 已验证历史与逐步预测核对

日期：2026-09-25

## 目标与边界

用户选择先实现 Retrodict 式的“已验证日志＋预测核对”，再继续 P7 付费二关扫描。目标是让新会话看到同一题已重放首关的动作因果证据，并让已理解的多步计划在首次预测不符时停止。当前二关只继承游戏状态，未继承首关观察；`act_and_observe()` 只计算差分，不核对预测。此次保持 ARC SDK 的动作、关卡顺序、动作上限、30 分钟与 5 分钟无动作停止线。不会读取游戏源码、其他题目或未验证运行，也不会自动执行旧会话代码。

本设计只借鉴社区公开方法，不复制第三方实现。Retrodict 的完整工作区、视觉模型、上下文重置和多层升级策略不在本次范围。

## 方案选择

1. **采用：已验证历史＋逐步预测核对。** 在 P7 应用层提供有界历史查询和有预期结果的动作队列；模型仍可用单步动作探查未知规则。可直接衡量二关是否少走无效动作。
2. 只传首关文本摘要。实现较快，但丢失逐步观察，不能用历史证伪规则，也无法防止错误长队列。
3. 一次实现完整 Retrodict 工作区。覆盖更广，但会同时改变执行、记忆和模型策略，无法判断哪项改善有效，且维护面过大。

## 证据与数据流

`VerifiedPrefix` 仍由现有 `load_best_prefix` 选取，必须通过身份、封存、回放和摘要校验。P7 操作员在把该前缀重放进本次游戏时，逐动作收集动作前后**动画末帧**、动作、稳定状态差分、关卡数和状态。首帧记作序号 0。当前二关的新动作沿用同一收集器，形成只属于本次 game ID、seed、run ID 的连续记录。原始帧和完整记录仅存于私有运行证据或应用内存，不进入公开回执、网页或通用框架协议。

工作进程通过原有受限 P7 socket 获得只读的 `history(start, limit)` 和 `frame_at(sequence)`；`history` 每项包含序号、动作、变化格子的有界摘要、前后状态哈希、关卡数和游戏状态，`frame_at` 只返回已发生步骤的一张稳定网格。请求有固定页长和字节上限；过界、未来序号或身份不一致时拒绝，不截断成看似完整的记录。模型可据此在当前 Python namespace 写规则假设并拿既有步骤检验。应用给出的摘要只陈述观察事实，不把猜测标成规则。

## 动作预测与停止

保留 `act()` 供**单步**未知规则探查。新增 `act_checked(plan)` 供多步计划：每项含现有合法动作以及至少一项有区分力的预期，即指定坐标的稳定颜色值、完整稳定网格哈希、关卡增加或预期进入的终局状态。仅写“关卡不变”或“仍在进行”不足以提交多步队列。P7 客户端逐项执行，每步后比对稳定末帧；首次不符、动作不可用、GAME_OVER、关卡变化或已达到动作上限时，立即停止未执行的队列，返回实际观察、差分、不符的预期和已执行数。不得事后把未执行动作计入 SDK 或 token/动作账本。队列最多 20 步，不能绕过 Broker 的身份、顺序和动作校验。

共享提示词要求先查询历史、写可由历史证伪的规则假设；未知机制只做单步探查；理解后使用 `act_checked` 并给出预测。检查结果来自代码，模型文字不能自行宣称预测通过。普通运行和官方入口使用同一套 P7 应用逻辑；研究配置可明确选择旧行为作为 A/B 对照，记录变体，不改变官方提交逻辑。

## 故障与验证

收集历史或校验预测失败时停止该计划，返回固定的私有安全错误，不默默继续动作。前缀来源、摘要或首关边界不符时在模型启动前失败。历史查询只能读取已发生且属于本次 run 的记录，数据深拷贝，外部改写不能影响 Broker。公开输出继续遮蔽原始帧、规则假设、模型内容和私有路径。

零模型测试覆盖：真实封存首关前缀重放后的历史连续性与最后一帧；错题号、seed、摘要或未封存前缀拒绝；分页及未来序号拒绝；预测匹配时继续、首次不符时剩余队列不执行；关卡边界和 GAME_OVER 停步；动作数与 trace 一致；公开输出不泄露帧。随后用同一题的已保存二关起点做有限 A/B：固定 DeepSeek Flash、动作上限与时间线，比较过关、二关新增动作、首次有效动作前用量、重复无效动作。历史日志与预测核对是否改善成绩必须以这次对照为准，不能由单元测试推断。
