# P7 continuous-consequence rollout experiment

User-approved direction: learn game rules, unfold action consequences to a boundary, replay death counterexamples, and inspect candidate routes. This is a P7 experiment, not a common Prime strategy or a new safety certificate.

## Contract

A pure Python P7 helper supplies rollout(initial_state, actions, *, transition, settled, terminal, collision=None, max_ticks_per_action=128). State is finite JSON. The actor supplies its model callbacks; one input is sent only at the first tick of each action, then transition receives None until a stable, collision, terminal or unknown boundary. Actual environment actions are never dispatched. Model callbacks own domain semantics; helpers do not read hidden engine state. Input copies are immutable to callers. Full state participates in cycle detection. Exceptions, unknown classification, cycles and tick exhaustion report unknown with the reason and actual limit. Callback wall time remains bounded by the existing IPython execution host, not this tick count.

replay_cases evaluates the same model against declared cases and emits history-compatible predictions; replay_deaths assembles all current-run actual GAME_OVER transitions from read-only history and initializes each from its actual prior frame. It does not load previous runs. Missing or corrupt evidence cannot silently pass. References identify exactly which observations and actions were checked. The existing host publication comparison remains authoritative for historical predictions. A replay match is model evidence, never proof of future route safety.

evaluate_candidates unfolds each candidate input sequence. Model-predicted deaths are excluded from its returned model-relative candidate set; unknown candidates remain available. A failed/unknown supplied backtest downgrades candidate judgment. Returned results carry execution_authority=none. Collision is not death and terminates evaluation at a partial boundary; unexamined suffix stays explicit. No new compulsory publish/checkpoint/NOTES gate or mandatory plan field is introduced. Real action admission remains unchanged in this phase; future model-driven veto needs a reviewed, host-recomputed binding and remains separately unimplemented.

## Approved follow-up: per-action rollout and explicit fatal-risk reports

This supersedes the optional-call policy above. Task48 is stopped; no new live game is authorized. The user approves automatic rollout before every real primitive and separate records of actual LLM-initiated rollout calls. Fatal-risk screening takes priority over finding a route. The user explicitly selects: predicted death or an identified conditional fatal branch stops the current action and the plan suffix, returning evidence to the LLM; ordinary incomplete models produce an explicit warning but do not block exploration.

Risk and dynamics are independent. `rollout` accepts optional `risk_check(before, after, action_or_none)` returning explicit findings with `id`, `type`, `condition`, and `evidence`. Finding types are `predicted_death` and `conditional_fatal`; callbacks inspect copied states after each transition before accepting settled. The risk report preserves findings plus coverage, with summary statuses `predicted_death`, `conditional_fatal`, `unassessed`, or `no_identified_fatal`. The last status describes only checks performed, never a safety certificate. Missing/erroring checks, unknown dynamics and unexplored suffixes remain explicit. A failed backtest reduces model confidence without erasing a raw death warning. The helper cannot infer game semantics from arbitrary JSON, colors or natural-language notes.

The P7 application explicitly registers actor-owned model callbacks in its existing persistent kernel. Before each action, the host evaluates that registration using the latest settled frame, exact observation reference and action, including automatic consequences. No hidden engine, previous-run model, new registered tool or common Prime mechanism is introduced. Missing registration returns unassessed. RESET has an explicit recovery boundary; RESET, level changes and kernel replacement invalidate prior registration.

The host records model revision/generation, observation/action binding, actual call origin and measured computation cost. Automatic calls do not count as LLM-initiated calls. Matched active calls are evidence about the exact candidate, not evidence inferred from source text or generic tool counts. Missing proactive coverage can thus be compared with the host's independently computed fatal-risk findings. These records cannot prove why the LLM internally skipped a call or guarantee future proactive use.

The runtime reuses the same kernel. Computation must release the Solver lock while retaining exclusive plan execution, then recheck observation, kernel generation and cancellation before dispatch. Plan idempotency, preconditions, unknown environment results and existing action/observer stop boundaries remain effective. Risk stops are not dispatched actions and do not consume a paid game action. Only the research entry receives experimental usage instructions.

Verification is scoped to fatal-risk preservation, conditional risk before settled, copied-state callbacks, each-step fresh state, explicit missing model, proactive/automatic origin, fatal veto without dispatch, cancellation and unchanged idempotency. Installed-wheel persistent-kernel verification and required promotion checks are provider/game-free; live efficacy remains unverified until separately authorized.
