## P7 data interface

Add `r.patches(windows, sequence=None)` to the existing read-only research module. `windows` is a list/tuple of1–64 half-open `[x0,y0,x1,y1]` regions; integer coordinates exclude bool/float, each region is nonempty and entirely inside the settled frame. Aggregate output pixels at most4096, counting overlapping regions repeatedly. Reject oversized/invalid requests before copying output; no silent clipping or truncation.

Resolve omitted sequence once using current observation sequence, then read that exact historical frame. Return `sequence`, complete frame `shape`, and `patches` in input order, each with `window`, detached exact `pixels`, and exact color `counts`. Color counts and pixels have no background, object or danger semantics. Do not add observation refs that cannot be bound to the same read. Existing frame/server response limits and failure diagnostics apply. No new model-registered tool or writable endpoint.

Model programs can construct windows from their own grid/offset hypothesis and compare complete local shapes against their representation. The service makes validation convenient, does not guarantee its use or certify a model. Keep render/geometry/frame behavior unchanged.

## P7 research guidance

Add a brief current autonomous-prompt principle: distinctly different new shape/internal-color markings provide a candidate risk clue even before a lethal counterexample. Combine actual known motion/consequences with information value, failure/reversal/detour cost, and available alternatives; unknown markings are not automatically dangerous, and resolving every unknown is not a prerequisite for progress. A model's compressed rendering is an interpretation: compare complete patches when distinguishing shapes/coordinates matters, including after a view/phase change. No fixed game colors, route, mandatory form, per-step query or extra model call.
