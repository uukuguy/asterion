# P7 同题世界模型、回放验证与可执行路线设计

日期：2026-09-30  
状态：已确认设计，待按实现计划落地

## 目标

让 P7 在同一题的 L1→L2→后续关卡中积累可验证的机制、对象关系和路线证据，减少重复探索，并把离线优化结果转换为可检查的在线动作。设计必须适用于全部关卡，不包含任何题目、坐标、颜色或固定解法。

## 边界与不变量

- 记忆按 `game_id`、seed 和运行身份隔离，只在同一题内持久化；本阶段不做跨题规则迁移。
- 结构化 `WorldModel` 是语义权威；原始帧、动作和差分是证据源。模型文字不能替代代码验证。
- 全题机制和控制映射在确认后保留；进入新关卡只刷新局部对象、局部关系和当前状态。
- 候选事实必须带证据引用和置信度。假设最多进行一次有区分力的探测；冲突不会自动升级为确认事实。
- 所有在线动作仍经过现有身份、顺序、动作上限和取消控制；世界模型不能授权额外动作或绕过宿主策略。

## 数据结构

### WorldModel

按三层存储：

1. `mechanics`：动作槽位含义、可通行与阻挡、交互方式、撤销/重置、终局条件等。
2. `entities`：玩家、墙、地板、门、钥匙、目标、危险物、开关等对象及其属性。
3. `relations`：钥匙—门、开关—门、对象—目标、危险区域和可达性等关系。

每条事实或假设包含 `evidence_refs`，引用观察 frame、action、前后帧摘要、来源运行和置信度。原始帧不复制到公共回执；私有证据保留完整轨迹和摘要哈希。

### TransitionModel

`TransitionModel` 是从已确认 WorldModel 派生的有限、确定、只读转移假设。它预测动作对对象、关系、关卡和终局的影响，但不能修改真实游戏状态，也不能访问引擎源码、凭据或网络。

它必须先通过 retrodiction gate：对已有历史逐步回放，解释动作前后稳定帧、变化格、关卡变化和终局变化。不能解释历史的模型只能作为待验证假设，不能进入批量在线计划。

### Playbook

同题 Playbook 分为：

- `checked_model`：已通过历史回放和在线核对的控制映射、机制和路线片段；
- `level_memory`：当前关卡状态、已证伪分支、待验证边界和可重放片段；
- `evidence_index`：事实、假设、冲突及其 frame/action 引用。

Playbook 是派生索引，原始记录仍是唯一证据源。完成关卡后只压缩已验证内容，不删除原始记录。

## 学习与验证流程

1. 从新帧和稳定差分中提取对象候选。大片同色区域、连续直线、少数颜色、重复形状等只能生成视觉常识候选。
2. 将候选与同题已确认机制合并，生成待检验的对象和关系假设。
3. 构造 `TransitionModel` 候选并执行 retrodiction。所有已记录转移必须能被解释；否则降级为假设并禁止批量规划。
4. 为每个在线动作生成预期：语义变化、指定坐标值、稳定帧哈希、关卡增加或终局状态至少一项。仅写“仍在进行”不算有区分力的预期。
5. 通过 `act_checked` 批量执行，逐项比较稳定末帧。首次不匹配、动作不可用、关卡边界、终局或动作上限立即停批，未执行动作不进入账本。
6. 将实际结果写回证据，只刷新受影响的局部对象和关系。确认事实保持不变；冲突创建带来源的局部分支。
7. 关卡完成后，把通过回放和在线核对的内容写入 `checked_model`，并保存可重放的路线片段。

动作槽位不再被全局提示词固定解释。ARC-AGI-3 技术报告明确每个环境使用不同的动作子集，因此动作映射必须作为同题 `mechanics` 中的已验证事实，并由实际 `available_actions` 约束。

## 离线优化与在线注入

离线 ARC 引擎只接收通过 retrodiction 的 TransitionModel、已验证前缀和 Playbook 路线片段。每个候选必须在独立引擎中复现已知前缀并达到目标状态，同时生成逐动作预期。验证失败、候选变长、身份不符或引擎异常时，回退到当前已验证路线或单步探测。

优化器的产物是带预期的可执行动作队列，不是仅供模型阅读的另一串动作。在线 Broker 仍是最终执行门，批量首个冲突后立即返回实际观测并触发重规划。

## 失败恢复与升级

- 批量冲突立即停止，不继续执行剩余动作。
- 保留冲突前的确认事实，复制局部分支并记录冲突证据、影响对象和待验证边界。
- 同题私有模型继续可用；跨题证据和未封存运行不进入 Playbook。
- 连续无法解释、重复重置或达到配置阈值时，才升级构造更完整的可执行模型；构造失败回退到结构化事实和单步探测。
- 预测是否通过只由代码比较结果决定，模型不能自行宣称通过。

## 与现有 P7 的衔接

复用现有帧差分、`history`、`frame_at`、`act_checked`、前缀重放和离线优化器。新增能力应放在 P7 应用层，不改变通用运行时协议；私有帧、提示词、假设、凭据和本地路径不得进入公开结果。

Tycho 的参考点是每题的可执行 `State / transition / render / outcome` 假设，以及验证、修复或绕过模型的选择；Retrodict 的参考点是逐帧日志、历史回放门、动作预期、首个冲突停批和经验证 playbook。这里只借鉴机制，不复制其执行环境或具体代码：

## 验证计划

先做零模型验证：

- 无法解释历史的 TransitionModel 被拒绝；
- 预测匹配时继续执行，首个不匹配时剩余队列不执行；
- 关卡边界、终局和动作上限强制停批；
- L1→L2 重做复用同题确认机制和路线片段；
- 冲突只刷新局部状态，不破坏全题确认机制；
- 离线候选失败安全回退；
- 私有证据与公开回执严格隔离。

随后使用固定后端和有限预算做同题 A/B，比较首次有效动作、重复无效动作、关卡完成和动作效率。单元测试只能证明边界和数据流，不能推断通关能力。
