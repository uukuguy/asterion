# P7 WorldMap 驱动求解：整体设计审查

> 2026-10-05。静态源码审查与候选设计；未修改求解代码，未运行新模型或复现排行榜结果。本文不替代已批准的认知合同，也不宣告新架构已实施。

后续用户要求将网页控制台纳入求解，并允许不迁就当前实现的大胆重设计。整体推荐以 `docs/superpowers/specs/2026-10-05-p7-worldmap-solver-redesign.md` 为准；本报告保留源码事实，第 5 节是其初步方向，不是限制重构范围的兼容要求。

## 1. 核心结论

P7 已有可持续执行 Python 的 IPython 底座。主要设计问题是没有把这项能力组织成默认的解题工作流：模型理解游戏、编写可演算的规则、用历史调试规则、计算过关路线，再由真实反馈修正理解。

当前系统维护语义认知、WorldModel 分类事实和受限 MechanismSpec 三条知识通路。它们确实进入模型上下文，局部效果也确实能自动归纳、验证和搜索；不能称为空壳。但自然语言中理解的对象、隐状态、目标和策略，不能直接成为内置搜索使用的状态与转移。IPython 被 prompt 定义为分析或工具无法表达时的 fallback，模型主要在多种知识工具间自行协调。

PNG 输入是可选感知方式。其缺失不能解释全部求解失败，更不能据此把视觉接口置于 WorldMap 推理设计之前。源码证据支持优先重审模型表达、历史分析、目标推断、规划和纠错的整体连接。

## 3. 三套系统如何真正工作

| 设计环节 | Tycho | Retrodict | 当前 P7 |
|---|---|---|---|
| 真实证据 | 分关卡/尝试保留网格、动作、差分、终止证据及动画访问 | 全帧日志、动作、状态与差分；Python 解析为数组和对象 | Broker 有真实动作及 settled 帧查询；console 动画档案不是模型历史接口 |
| 工作模型 | 模型编写 `State/init_state/transition/render/outcome`；可包含隐状态 | 模型自由编写 `step(state, action)` 等游戏程序 | 语义 claim 与分类事实并行；内置模拟器使用固定 guard/effect 语言 |
| 建模控制 | Actor 判断何时请 builder；builder 只建模，不执行游戏动作 | 同一 actor 分析、编程、测试、搜索；卡住后指令升级 | 同一 LLM 协调认知、归纳、证书、搜索和动作工具；IPython 是 fallback |
| 模型检验 | 编辑模型后自动反馈；分别检查初始状态、动态、目标与终止画面 | 历史回测主要是 prompt 义务，runner 不签模型证书 | 自动归纳模型受完整当前历史回测及证书约束；语义 claim 另有证据分析 |
| 目标与搜索 | 模型定义 outcome、动作集、子目标、启发式和可选专用 planner | Python 自由表达目标、状态与有界搜索 | 内置搜索使用 frame/level/state；启发式缺少关内语义进展 |
| 执行纠错 | Canonical model replay 验证候选；逐动作保留 actor 决策，轨迹偏离时停止计划提示 | 队列逐步执行；预测不符、状态/关卡变化或动作失效后回调 actor | `act_checked` 已可执行带预测的短列表；部分自动模型计划另检查证书上下文 |
| 长期研究成果 | 可执行模型和 actor/builder 笔记在工作区，跨关总结 | Playbook 的 working model / working memory，加分析程序和原始日志 | 语义账本可持久化，kernel 名称跨上下文压缩保留；代码成果重建不是默认工作流 |

Tycho 的关键是可编程的抽象状态与 actor 主动使用建模能力。其 `State` 可表达库存、阶段、屏外地图和历史累积变量；`render` 把抽象状态投影回观察，`outcome` 单独描述目标。模型编辑立即得到历史检验反馈；搜索失败会区分目标错误、动作集合不足、未知地形、预算不足等原因。建模报告给 actor 可用的模型、证据范围、计划起点和待区分目标假说，而非只有文字认识。

Tycho 默认不是每步强制建模。获胜配置由 actor 主动调用 builder；模型未成熟时仍能推理和探索。建模或搜索与动作出现在同一工具批次时，代码会推迟动作，让 actor 先读计算结果再作决定。

Retrodict 的关键是完整可计算的历史与预测驱动的执行循环。模型可以自行编写解析、模拟和搜索程序，无需框架预先认识每种机制。执行器机械地跟踪预测和中止条件，遇到差异才重新调用推理。必须区分实现与提示：其 `expect` 实际可省略；“先回测模拟器”“每步写预测”“维护笔记”主要由 prompt 要求，不能称为所有动作都获机器证明。

源码锚点：Tycho `tycho/prompts/{actor,builder}.system.j2`、`tycho/agent/agent.py`、`tycho/workspace/agent_tools.py`、`workspace.py`、`templates/seed_{world_model,verify,plan}.py.tmpl`；Retrodict `src/arc3/{runner,prompts,tools,plan_parser,logwriter}.py`、`workspace_template/arclog.py`。

## 4. P7 的架构断裂

### 4.1 可编程能力已有，主求解策略却绕开它

`p7/live.py` 的 worker 在同一 namespace 中 `exec/eval`。模型可定义数据结构、规则、验证器和搜索函数，普通 Python 异常会返回 traceback 供修复。Prime 的 `SUMMARY_KERNEL_NOTE` 已明确变量、import 和 helper 跨上下文压缩保留。不能据其他应用的 worker 限制误判 P7 无法编程。

但 `p7/prompt.py` 将 IPython 描述为分析/fallback，并要求只导入 `p7_client`；重点指向大量专用知识操作与受限 simulator 工具。问题是默认研究和求解策略，不是欠缺 Python 执行器。真实 worker timeout/传输故障会丢失 kernel；程序代码与当前研究状态如何重建仍须设计，不能把压缩后变量保留等同于进程恢复。

### 4.2 描述规则与演算规则未形成明确交接

`planning_background` 确实提供中文稳定认知、WorldMap、模拟与回溯状态。每步动作也会更新局部 effect induction 并尝试自动晋升模型。缺口是：语义理解的规则和目标没有一条默认通路，交给 IPython 形成可调用的状态、转移、目标和搜索程序。

`MechanismSpec` 仅支持六种 guards、七种 effects；预测要求唯一规则匹配，模拟 entities 原样传递。对隐状态、库存、开关逻辑、多对象联动或屏外地图，这类局部像素变换语言很难承担通用游戏模型。继续扩充类型会把游戏理解负担转移给框架开发者。

### 4.3 当前 WorldMap 不是统一的规划状态

WorldModelSnapshot 主要分类保存 mechanics/entities/relations/hypotheses/conflicts。程序搜索节点是 frame/level/state，关内启发式缺少“离目标还有什么障碍”的语义距离。中文的目标与策略、模型中可计算的 outcome、搜索的子目标，是不同通路。公开 `p7_decision` 记录目标并不把它送入 planner。

这不要求程序替模型推导目标；要求模型推导的目标能进入其自行编写、检验、调用的求解程序，而不是一直停留在对话或 console 摘要里。

### 4.4 证据强度与策略置信度需要分开

10 月 5 日运行结束时保存的持久认知快照显示，“向上一小步成功”被用于确认“最短向上路线”，未测试的接触条件被用于确认成功条件。部分支持证据来自更早会话；不能据此声称错误认识是在该五动作运行中新产生。动态预测正确只支持该动态，不能同时证明目标假说、整条路线或最短性。

已确认的模型通路和语言认识都应保留适用范围、反例与未知条件。回测可以支持工作模型，却不能证明所有未见状态都正确。程序内搜索得出的候选路线不等于真实过关；真实 Broker 观察仍是最终证据。

P7 源码锚点：`p7/{prompt,live,ipython_host,broker,world_model,mechanism_model,model_search,cognition_narrative}.py`、`agents/prime/summarization.py`。本节是静态设计诊断；不能单凭这些断裂归因某场真实失败。

## 5. 候选方向与推荐

| 方向 | 收益 | 主要代价 | 判断 |
|---|---|---|---|
| 继续扩大内置 DSL | 复用现有自动归纳、证书和搜索 | 不断增加通用机制类型；语义与算法仍需额外交接 | 可保留为局部计算路径，不宜作为唯一通用解题模型 |
| 现有 actor + IPython 可执行工作模型 | 已有代码执行、历史查询和短计划执行；状态/目标/搜索可由模型表达 | 必须组织研究成果、模型检验与反馈循环 | 推荐作为 P7 默认求解工作流 |
| Actor + 按需专注 builder | 建模工作复杂时，独立上下文可减轻 actor 负担 | 增加模型调用和模型代码交接；不能仅交一段报告 | 保留按需扩展；不先强制每局新增 agent |

推荐保持现有 Prime/Pi、IPython、Broker、operator 与通用 runner。由 P7 应用组织以下完整循环，不另造 composer 或 runner：

```text
真实观察与历史
      ↓
WorldMap 工作理解：对象/隐状态、已知规则、目标假说、障碍与未知条件
      ↓
Actor 决定当前需要：直接推进 / 区分关键假说 / 建模计算
      ├─ 证据不足：一个有用途的探针，带可检查的预期
      └─ 规则足够：在持久 IPython 中编写或修订游戏程序
                    → 对历史回测 → 推演后继与目标 → 有界路线搜索
      ↓
候选短计划 + 关键预测 + 适用起点/假设
      ↓
现有 act_checked / Broker 顺序执行
      ↓
实际变化与预期差异
      ├─ 匹配：继续计划或新目标
      ├─ 不匹配：定位错误规则/隐状态/目标，修订同一工作模型
      └─ 新关卡：继承游戏规则，重建关内状态并检验新条件
```

### 工作模型与记忆

WorldMap 的稳定中文玩法描述继续作为主要可读规划背景。它记录对象、控制、规则和目标的当前理解；未定但有用的假说可参与规划。IPython 程序是这些理解的可计算表达，不要求每一句话都先形式化。

模型程序可自由选择适合该游戏的抽象状态，并按需实现：状态恢复、转移、观察投影、目标判断、候选动作、子目标、启发式及专用搜索。这里描述的是应用工作模型接口候选，不是新增公共协议。只需模型覆盖当前任务所需的规则；部分模型也可搜索局部目标，未知边界继续探索。

工作记忆只保留当前目标、障碍、开放的目标/机制假说、未访问状态、已经失败的尝试和下一计算任务。详细程序、原始证据与回测结果按需读取，避免每轮重新注入完整认知账本。程序、笔记、回测及当前计划应指向明确的模型版本和证据范围；kernel 丢失后从代码与真实当前观察重建，不能把旧变量或旧计划直接续接。

恢复只加载纯模型源码、数据和已分析历史序号，不重放可能包含真实动作的旧 cells。现有每 cell 默认 16 KiB/60 秒、输出约 12 KB 的限制应指导计算组织：长搜索分块保留 frontier，回测输出摘要。先以纯 Python 为可用基线；当前 worker 是否提供 NumPy/SciPy 须按实际打包环境核验，不能从整个仓库 lockfile 推断。

### 检验、探索与执行

模型检验分别反馈动态、目标与覆盖范围。局部状态预测、目标谓词和策略最短性不是同一项结论。假目标、隐藏状态遗漏、搜索预算耗尽与真正已观测反例须能区分；“没有搜到”不说明无解。

建模不是普通探索的前置审批。Actor 能依据部分认知选择动作，只在计算有助于求解或区分关键假说时建模。卡住时重新检视未解释证据、错误目标及探索前沿，不用重复动作或增加认知条目代替推理。

真实动作继续唯一经过 Broker。现有普通 `act_checked` 短列表支持 1–20 项且不要求 MechanismSpec 证书；带自动模型 `context` 的 envelope 才检查 ModelCertificate。IPython 自行推演的动作可以作为普通 checked 探索候选；其计算结果不自动变成受证书认证的模型计划，也不授予执行权。跨关、预测失配或模型修订必须使旧计划失效。

受限 DSL 的自动归纳可保留为有用的辅助计算。它不应排斥模型在现有 IPython 中表达更适合游戏的规则。`D-2026-10-01-01` 仍是当前已批准的自动 planner 合同；若候选方案扩展其模型来源或证书语义，须在实施前明确修订，不能悄悄让任意 Python 冒充当前受认证模型。

## 6. 验收与未完成边界

第一轮能力验收固定新局、同游戏/seed、有限应用预设；不载入已知完整路线、不用人工轨迹，也不调用真实 SDK 离线搜索供模型抄路线。历史来自本局已付出的在线动作。

检查真实过程：模型是否提出可用目标；是否在 IPython 中计算或调试当前规则；规则怎样改变路线；预测失败怎样修改模型；最终真实关卡状态和动作数。语言介绍变长、WorldMap version 增加、回测通过或执行器通过测试，都不能替代过关结果。

随后检查同一游戏下一关，以及只复用理解/程序、不复用精确动作路线的再次求解。只有这些真实结果能支持能力改善；不能从参考系统成绩直接推断 P7 也会达到 100。

历史证据须精确归类：9 月 30 日 VC33 WorldMap 阶段被旧路线和离线搜索辅助，不能算纯 P7 能力；10 月 5 日控制台在五动作后被主动停止，不能当求解失败；已有其他 L1 成功记录也不能自动当成全新冷启动。因此当前问题是缺乏有说服力的 WorldMap 驱动求解闭环证据，而非字面上从未发生任何过关。

下一动作是确认整体候选设计及已有合同的适用边界，再制定一份覆盖默认推理循环、IPython 研究成果、反馈与真实求解验收的实施计划。不要将本审查拆成没有共同验收目标的工具补丁。
