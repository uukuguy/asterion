# Task29 动态观察边界：实现与评审记录

本轮针对 Task28 的两个缺口：L2 在动作批次中出现新视窗，模型未能及时重新决策；L6 未正确复用滚屏前已见的危险位置。用户授权完成设计、实现，并一同修复影响三层运行的直接相关缺陷。本轮不开展新 BP35 冷测。

## 最终行为

自主计划默认 `stop_on_view_change:true`。每个已确认步骤比较前后真实像素，存在有支持且不含歧义的平移候选时，若还有后续步骤，返回 `stop_reason='observation-boundary'`、最新画面和引用、已执行数量及未执行后缀。模型自己判断继续、修订或研究，并用新 plan_id 和当前起点提交；原计划只返回已有记录，绝不自动续执行。

模型可设置 `stop_on_view_change:false`，以批量执行其模型已经覆盖的视图变化；也可在任一步设置 `observe_after:true` 主动取得观察后再判断。软策略不能绕过终局、RESET、预测前置条件、未知执行结果、暂停、预算或取消。

**反馈是像素对应候选，不是危险判定。** 没有硬编码 BP35 的颜色、连续上浮、相机坐标或路线。未检出平移也不意味着安全；机制不能中断单个 SDK 动作内部，不能识别所有物理相位变化或自动补全空间记忆。

## 三层归属

| 层 | 本轮职责 |
| --- | --- |
| Prime 通用层 | 复用已有工具调用、返回、admission、预算及记录保障；不另建执行器，不注入游戏认知流程。 |
| P7 研究层 | Solver 的计划边界与模型选择；模型自组织转移模型、历史空间关系和后续研究。 |
| P7 数据层 | 有界像素平移测量与真实历史引用，保持候选及不确定性，不提供隐藏引擎信息。 |

数据比较最多4096像素、129个水平或垂直位移候选，不搜索斜向；使用统计背景众数与双端信息像素，对比零位移和次优候选，避免平坦画面、重复纹理及局部角色移动冒充可信平移。无新增依赖。只读 `r.view_change(before_sequence,after_sequence=None)` 可复核相同测量，返回实际序号、观察引用及可用的原始像素 hash。

检测异常在动作交易处理之外隔离：已确认动作仍保留、计费，默认只停止未执行后缀，不把结果改成未知、不永久封锁环境。数据超限或歧义显式保留，不作为危险强制暂停。

## 一同修复的重要缺陷

**RESET 硬停止被软失配绕过。** 真实反例中，RESET 配错误预测且 `stop_on_mismatch:false`，原代码继续执行下一步。现在根据已确认的实际动作独立停止 RESET 后缀；真实 WIN、GAME_OVER、换关也优先于软失配。失配差异仍保留，不能把它说成匹配。

**新增反馈使合法计划在完成后返回失败。** 评审使用实际 Solver/Broker 的20步合法计划复现：所有20动作已执行，测量统计和引用累计使60KiB投影上限溢出，返回抛错。移除新增字段的对照正常返回40131字节。修复分级压缩模型副本：先摘要重复测量统计，若仍超限，再减少重复的像素预测和差异示例，并累计明确省略数量，保留 origin、状态、位移、露出窗口、解释与前后证据引用，明确记录省略统计及历史重新读取入口；不扩大上限、不改原始结果、不退款或重派。
