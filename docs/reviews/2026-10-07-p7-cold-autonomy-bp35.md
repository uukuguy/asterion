# P7 分层自主研究与 BP35 L1–L6 冷启动验证

> 2026-10-08 终局：**目标六关失败，完成五关 / 213 个研究动作 / 5400 秒**。本次优化效果不理想。下面将实际研究过程与原版 arc-skill、旧 P7 成熟路线分别对照；软件测试通过不代表六关能力通过。

## 截止时间应该约束什么

固定提交的原版 arc-skill 没有整场解题或单关硬截止时间。其 RPC、启动、局部搜索有各自的限时；online 模式约十五分钟的闲置租约也不是解题总时限。模型宿主仍可能施加上下文、调用次数和任务预算。本次原版实测的有限总预算来自我们的实验宿主，不是 arc-skill 的解题机制。

P7 的旧 900 秒来自研发时期的快速 witness 预设。它能证明“该版本在 900 秒内做到哪里”，不能把时间耗尽解释为模型已经充分研究后仍无法过关。原版 arc-skill 的 L6 自然回合约 1128 秒，模型在约 864 秒 RESET、约 1102 秒过关：同样截在 900 秒，只能得到未完成记录。增加时间也不能单独证明旧 P7 会通过。

新设计把三个问题分开：

| 约束 | 谁负责 | 含义 |
|---|---|---|
| 任务总预算 | operator / host | 授权一次研究最多使用多少时间、模型调用和环境动作；从任务准备起计 |
| 单次执行限时 | runtime / 工具 | 执行等待的有限边界；本次 Pi 限时覆盖整个 RPC 研究轮，不是每个底层模型请求独立分片 |
| 任务是否完成 | 应用权威状态 | 根据实际目标、环境与终止原因判断；模型自然结束一轮不等于目标完成 |

暂停、自然续跑、RESET 和研究 kernel 重建都不刷新总预算。停止研究后的清理另有有限宽限期，期间不再授予模型研究或新的探索动作；保存所需的证据重放单独记录，不计作新增解题研究。研究时间耗尽、真实环境终局、工具零派发拒绝与预测失配要分别记录。900 秒 witness 保留；正式长程研究使用显式有限 profile，本次为 5400 秒，而非给所有场景硬编码一个新的单关时限。

后续若研究需要续期，应作为新的明确授权记录，保留先前的未完成证据和累计成本；不能让每次自然结束都自动获得一份新预算。任务状态与预算状态互相独立，方便其它研究任务复用同一组织方式。

## 已实现的分层职责

| 层 | 实现及责任 | 不在这一层的责任 |
|---|---|---|
| 通用 Prime 研究会话 | 复用已有执行 kernel 与 Pi RPC 持续会话；绝对截止时间、自然轮数准入；通用研究指引 | ARC 地图、RESET、动作语义与过关判断 |
| 应用 / operator | 注入目标、权威任务状态、当前观察与工作区；配置有限 profile、取消与清理 | 替模型决定研究假设、下一实验或解法 |
| P7 ARC 适配 | 将 ARC 状态和反馈交给模型；逐步根据真实当前帧选择派发证据；全量预测比较与失配截断 | 新造第二套研究 runner，或把 BP35 规则写入框架 |
| 研究执行基础设施 | 持续 Python、显式 source/JSON 导出与恢复；本次 operator 的文件读取边界 | 默认读取旧答案、游戏实现或凭据；恢复不确定环境动作 |
| LLM | 自选表示、假设、语言笔记、计算、实验、预测修正与 RESET | 扩大授权预算，或自行声明环境已过关 |

新 `PrimeContinuationBudget` / controller 管理同一绝对截止时间和最多自然轮数。它只是轮次准入；正在执行的工作仍由原有取消、控制和 guest 截止路径约束。没有另造 runner，也没有修改闭合公共协议。

通用指引允许模型按需维护事实、假设和待研究问题；语言笔记、局部模型与程序计算均可使用。真实反馈优先于先前假设，局部搜索无路不能当作环境无解。它不要求固定研究阶段、完整程序模型或先搜索后行动。通用层已有非 ARC 的假研究任务测试；本次端到端只验证 Prime/P7，未验证 Native 或其它领域的任务能力。

## P7 此次修正的具体阻碍

1. **P7 原来没有接通持续 Pi 会话。** 框架已有 reusable 接口，但旧 P7 自然轮次使用一次性的 RPC run，轮间保留 Python 研究状态不能等同于保留同一个模型会话。新 autonomy profile 明确启用已有持续会话，仍按同一总预算续跑。
2. **可恢复的失败不再被误判为整个任务完成。** 应用通过权威 task status 判断是否继续；`active` 和 `reset-required` 保持未完成。模型自行选择 RESET，host 不代替模型操作。达到目标、动作上限或不可恢复停止则终止。
3. **多步计划每次派发都使用真实当前帧。** 旧翻译选择依据计划起点，可能丢失后续步骤真正的变化证据。现在结构校验仍在派发前完成，grounding 在每次动作前选择，派发后仍比较原计划的全部 cells。不是新增原本已存在的多 cell 评分。
4. **合法的不变像素实验保留有限通道。** 精确当前观察绑定、尚未试过的动作可以使用既有 novel/probe 预算；返回仍如实标记 no-change，重复无效动作仍拒绝。32 次限额按 level/RESET episode 计算，不是跨 RESET 的整关额度。
5. **冷启动与恢复边界显式化。** 不加载旧 prefix 或经验。研究 kernel 重建仍使用相同受限 worker factory，仅恢复显式导出的 source/JSON，不回落到不受限 Python。

这些改动不证明所有历史卡点都已解决。原版 arc-skill 实测自行完成笔记、探针、预测调整和 RESET，没有自主执行等效的 79 源认知隔离或旧 P7 的上下文诊断。本次冷启动隔离旧材料，也不会测试暖状态下自主判断何时应隔离旧认知。

## 工具组织中尚存的负担

独立静态审计发现，当前 P7 虽不强制完整程序、搜索或模型发布，但初始行动、真实失配、RESET、level edge 和 kernel 校准后，仍有先提交结构化语义修订、取得新 revision，再提交下一计划的门槛。这里的“结构化”不代表必须先建立完整世界模型；但它确实比原版 arc-skill 普通 act 多出有数据依赖的事务。

另外，action labels 在 schema 中可选，提示和工具说明仍要求逐次提供；单独 `NOT_FINISHED` 预测的 schema 接受范围与 Python 校验存在歧义。这些是静态接口发现；本次未建立 action labels 或状态歧义与实际耗时、拒绝之间的因果。语义门槛的实际使用计数见下文。两次工具事务也不能直接折算成固定的两次 LLM 推理回合。

此次冻结运行不热修这些接口。终局已区分 actor 实际选择的研究步骤与宿主真正强制的步骤，后续据此评估简化：保留观察身份、实际反馈、权限、累计预算与不确定动作不重发；让记录和表示服务于模型需要，减少把研究材料更新当作普遍动作准入条件的门槛。提供持续会话并不等于已经移除了所有流程负担。

## 主要机制：把研究错误、接口成本和等待分开

**1. 研究策略未收敛，是动作消耗的直接原因。** L1 有交互辨识、sprite / camera 表示校准与探索，前四关包含这些真实探索与校准动作；尚不能把相对成熟路线多出的 19 步逐项归因，也不能全算工具仪式。L6 的 15 次撤销、状态误读后的绕行、后期串行阴性机制试验均可定位。它仍有自主纠错与探索，却没把学习整理成有效路线。不是旧式“局部模型没路，所以不再实验”，也没有 L6 零派发阻塞。

**2. 强制语义修订放大实验事务，但不能承担全部成本。** 171 个工具事务 = 62 plans + 50 语义提交 + 1 checkpoint + 58 cells。50 次语义提交中 **29 次清除硬门槛、21 次主动提交**；不能全部称为强制 revise，完整 method 账也不足以把全部提交认定为 revise。

| 关卡上下文 | plans | 语义提交：硬门槛 / 主动 | cells | checkpoint | 合计事务 |
|---|---:|---:|---:|---:|---:|
| L5 | 6 | 1 / 4 | 10 | 0 | 21 |
| L6 | 16 | 9 / 6 | 14 | 1 | 46 |

L6 的九次硬门槛是入口一次与已修订的八次真实失配；最后一次失配后直接到截止。一次正确组织的机制试验也可能给出阴性反馈；当前接口仍要求先完整语义提交、得到新 revision，再提交 plan，形成两个依赖事务。ARC 普通 act 没有这道完整档案门槛，可以同一命令写笔记并行动。这里有明确的事务放大，却没有逐请求时钟证明每道门槛耗时多少；两个事务也不必然等于两个模型 callback。

两个 prefix 拒绝都发生在 L2 的 sequence50，其中一个 plan 零派发；后继修正断言后继续。它们不增加 paid，不是游戏反例，不能解释 L6 卡点。全程 23 个真实预测差异采用完整 cells 评分；ARC 多为单 cell，因此低 miss 不证明完整模型更准确。

**3. 一轮一直运行到截止，续跑能力未起作用。** 外层 controller 在自然 RPC 收尾后才准入下一轮；本次没有收尾。保持同一会话能保存学习，但并不自动形成有界研究段、阶段收口或摘要策略。预算实际可见，actor 也查询过 `context.budget`，不能归因“它不知道时间”。总预算有效，不等于研究节奏有效。

**4. 上下文增长明显，大部分壁钟仍缺可靠归因。** 58 cells 的执行 elapsed 合计仅 **1.391 秒**，L6 14 cells 为 0.487 秒，没有 kernel-loss。这排除了本次 Python CPU 搜索耗尽 90 分钟的解释。L6 两次动作之间最长间隔 367.017 秒，期间有研究操作；没有完整 provider 请求起止，不能称作一次网络卡死或纯模型思考。

171 条 usage 的 normalized input 合计 19,179,445、output 134,227；单条输入从 6,994 增到峰值 255,820。峰值是第 127 条 usage，发生在 L5 已通过、L6 首个动作之前；紧接第 128 条降至 41,315，随后再增长至末条 138,388。输入合并缓存字段，不是独立文本长度或账单量；没有完整 native 事件确认压缩原因。ARC Stage2 input 差量 9,541,852，其中 cached 9,139,328，output 23,204；两套宿主口径和范围不同，不能宣称 ARC 上下文更小、计算推理倍率或费用倍率。后续必须补计量再判断延迟主因。

## 追加审计：研究记忆与执行历史

用户指出，进入 L5 不应继续携带 L1–L4 的完整过关过程。当前设计应以有效研究信息组织模型上下文：前关带来哪些仍适用的机制认识、哪些假设已被反例否定、还有什么问题；完整动作、棋盘、旧代码和旧计划留在可检索档案中。仅缩短 JSON、提前触发通用摘要，不能代替这种内容选择。

### NOTES 实际有多大

| 记录 | 字符数 | UTF-8 字节数 | 行数 |
|---|---:|---:|---:|
| ARC L5 结束 | 662 | 666 | 9 |
| ARC L6 十次更新范围 | 509–913 | 511–915 | 7–9 |
| ARC L6 最终版 | 777 | 779 | 9 |

L6 十次写入全部是整体覆盖：八次 shell 重定向、两次文件写入，没有把十版笔记追加成日志。笔记保存当前研究摘要，并随新证据修订；相邻版本通常只保留三至四行旧文本，多版比前版更短。内容混合机制认识、负面证据、仍待检验的假设和当前计划。`start/status` 显示 NOTES；普通 `act/batch/reset` 的结果不自动附带 NOTES。RESET 不清空笔记，同一目录重新 start 也不覆盖已有笔记；过关时归档当时笔记，但活动笔记仍由模型主动更新。它提供的是持续可改写的短研究记忆，本身不负责缩短模型宿主的全部聊天历史。RESET 前还另存过辅助材料，且前后沿用同一模型会话；本次没有证明清空全部会话、仅靠这份 NOTES 就能恢复并通过。

**NOTES 不到 1KB 与 P7 输入 25.6 万 tokens 不是同口径比较。** 原版 ARC Stage2 的宿主输入峰值也曾达到 220,388 tokens。进一步检查 P7 的 51 个已存 workspace 版本（含初始版）：单版 WorldMap 的紧凑 JSON 最大仅 **1,873 UTF-8 字节**，中位数 **1,485 字节**。这些是存储字段大小，不是模型实际 token 数。研究快照本身并不需要几十万 tokens；应调查的是当前有效快照和模型长期历史之间的关系。

### P7 的确切缺口

已有 `b5c24693` 压缩在本次冻结版本中仍有效：revise/publish 成功只返回 ACK，删除 WorldMap/model/task/reports/board 回显；行动结果包含最终观察、逐步反馈与未执行后缀，**不包含整个 workspace**；IPython 也不自动附完整 context。初始输入、续轮和显式 workspace read 才会发送有界的完整研究快照。不能再把问题描述成“每次工具都回传全部研究状态”。

但 WorldMap 在外部存储中整体更新，并没有同步替换模型历史里的旧 WorldMap 工具入参、代码、计划、棋盘与结果。旧入参与执行结果随 Pi 消息历史积累，应用没有按研究任务边界同步选择、撤下或替换旧内容；Pi 原生压缩可能另外改变当前模型视图。更新了知识文件，不等于更新了模型的有效记忆。这是已确认的结构缺口；各类内容占本次模型输入多少，因完整 stdout/bridge 回复未存，仍不能精确拆分。

单次 context/plan/output 的容量限制只约束每条交付。`compact_events=True` 只压缩 Pi 返回 Python 的事件记录，不会压缩 Pi 发给 LLM 的历史。项目的 context-witness 模块没有在本次 P7 接线；不能用它的存在宣称已有研究记忆管理。静态依据见 [模型交付投影](../../src/asterion/applications/prime/p7/actor_projection.py)、[Solver](../../src/asterion/applications/prime/p7/solver.py)、[研究 runtime](../../src/asterion/applications/prime/p7/research_runtime.py) 与 [Pi 适配](../../src/asterion/runtimes/pi_rpc.py)。

### 对耗时与后续设计的影响

上下文增长应列为优先调查项，但“L6 未收敛”只是结果描述，尚不足以解释 harness 对推理的影响。峰值后输入已在 L6 开始前大幅下降，不能把该关全部约 36 分钟都解释为始终处理 25.6 万 tokens。长输入、重复生成结构化参数、多次串行请求和研究决策共同影响总时间；缓存命中会改变输入处理成本。官方 [延迟指南](https://developers.openai.com/api/docs/guides/latency-optimization) 与 [缓存指南](https://developers.openai.com/api/docs/guides/prompt-caching) 也要求分别考虑输入、输出、请求次数与缓存。当前没有足够计量给出百分比归因。

下一版应先明确一个通用契约：**模型整理当前有效认识，harness 维护对应的模型视图，完整原始过程保留引用和检索。** 当前任务的事实、竞争假说、关键反例、适用范围和下一研究问题可以持续修订；已完成阶段的详细执行过程退出常驻视图。任务切换与知识失效属于通用研究组织；P7 提供关卡边界和 ARC 观察，不能把关卡逻辑写入通用 runtime。笔记格式与研究方法由 LLM 选择，不能再引入一套每步必填的大表。

这项工作不能只调低上下文上限或强制缩到1KB：应验证模型能保留有用学习、取回原始证据，并撤下已失效认识；同时保持工具调用/结果配对、未知动作不重发、恢复和预算边界。本轮仅完成审计，尚未实施新的上下文组织机制。

## 可以学习的机制与分层改进方向

| 层 | 下一步候选 | 保留的边界 / 验收问题 |
